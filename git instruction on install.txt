--> Always use git status after every git command to see the status of the repository.

--> Git has three key areas:- ** Edit files → (git add .) → (git commit -m "comment") first comment should be "initial commit". **

1. Working Directory – Where you edit files. i.e the folder where you open git bash here.

2. Staging Area – Where you prepare files which are going to be committed. 

3. Repository – Where committed changes are stored permanently or it is a checkpoint.
 
--> (git init) --> means making that folder tracked by git as a repository.

--> It create a hidden folder in the same repository name .git where all the snapshots are saved by git.

--> (git add index.html assets/ about.html) or (git add .) for all files once to bring the files or folder to staged area.

--> (git status) to track and show the status of the repository. i.e which files or folders are modified, untracked, tracked, staged, committed etc.

--> (git log) all commits with details.
--> (git log --oneline) all commits in single line.

**NOTE** --> never run (git init) command inside cloned repository becoz it is already tracked by git the moment we cloned it.

--> (git clone url) --> it will clone the whole repository from github of anyone. make sure when cloning do in different folder outside of current repository folder.

-->Files in Git move through three main states: ** working Directory → git add → Staging Area → git commit → Repository  **

1. Untracked – not being tracked yet.

2. Staged – ready to be committed.

3. Committed – saved permanently in the Git history

--> (git restore file_name) to restore a file to last committed state.

--> (git restore --staged file_name) it is used to unstaged the file back which have been staged but it does not revert any changes made inside the content of the file.
or
--> (git reset HEAD file_name) to remove files from staging but keeps changes.

-->(git restore .) this permanently discards uncommitted/modified changes in the file . ie someone add malicious or unwanted data in the file.

--> (git diff) shows unstaged changes have been made recently in files.

--> (git diff --staged) shows staged changes in files.

--> (git diff HEAD~1 HEAD) it compares the last commit with the current one.

--> (git commit --amend -m "previous commit msg") it ammend the previous commit 

--> (git add forgotten.txt) stage the forgotten file.

--> (git reset --soft HEAD~1) undo last commit keeps changes staged.

--> (git reset HEAD~1) undo last commit keep changes unstaged.

--> (git reset --hard HEAD~1) undo last commit an discard changes.

--> to make git ignore certain files create (.gitignore) file in the repository and then add the names of those files with their extension.

**Common files to add in .gitignore**

# Ignore specific files

secret.txt
config.env

# Ignore all file types-

*.log
*.tmp
*.cache

# Ignore directories/folder:-

node_modules/
build/
dist/

# Ignore files in any directory
**/*.bak

--> (git rm file_name) del/remove the file from directory/folder/repo.

--> (git rm --cached file_name)-- (stop tracking file) it deletes the files from the repo. but keep it as untracked file in the directory/disk.

--> (git mv old_name new_name) it rename the file.

--> (git branch) view the name of branches.

--> (git switch -c branch-name) create a new branch beside master branch.

--> (git switch branch_name) switch to other branch.

--> (git merge branch_name) merge a brach with master branch.

--> (git branch -D branch_name) delete the branch.

--> (git checkout --ours file_name) to consider our file during merger conflict.

--> (git checkout --theirs file_name) to consider their file during merger conflict.

**or manually remove the markers in vs code editor to resolve the conflict** then add and commit the file to complete the merger.


**GIT-HUB**

--> (git remote -v) it shows the remotes github_url of push and fetch.

-->(git branch -m main) change the name of master branch to main for github.

--> (git remote add origin github_url) it setup the git_url where we upload our git repo.

--> (git remote set-url origin github_url) it change the remote url.

--> (git push -u origin main) it is a first push/upload the repository to the github.

--> (git push) regular push

--> (git push origin branch-name) it push specific branch.

**We can directly edit and commit changes in github directly and commit it to main branch however we have to fetch the information on git terminal on pc to update on our system**

--> (git pull) it is *fetch+merge*

--> (git pull origin branch_name) pull specific branch

** Fetch Changes **

--> (git fetch) Fetch without merging

--> (git fetch --all) Fetch all remotes

**Branch management**

--> (git branch -r) list remote branch

--> (git push origin --delete branch_name) delete remote branch

**GIT STASH** temporary save uncomitted changes.

--> (git stash) temporarily saved the unstaged & uncomitted changes. but will not show on (git status) it show working tree clean.

--> (git stash list) list all stashes

--> (git stash apply) apply most recent stash 

--> (git stash apply stash@1) to apply specific stash

--> (git stash pop) apply and remove from stash list.


Command 
git stash- Save changes to stash
git stash list- List all stashes
git stash apply- Apply stash without removing
git stash pop- Apply and remove stash
git stash drop- Delete a stash
git stash show- View stash contents
git stash clear- Remove all stashes
git stash branch [name]- Create branch from stash
